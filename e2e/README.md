# Браузерный тестовый модуль

Один одноразовый контейнер с Chromium и Playwright Test 1.63.0.
Версия npm-пакета совпадает с версией официального Docker-образа.
Это третий модуль стенда, подключённый через Compose-профиль `test`.

## Запуск

Сначала запустите локальный стенд обычным способом. Затем из корня проекта:

```bash
bash scripts/test.sh
```

Команда экспортирует актуальные ссылки демокурса из `demo.json`, собирает только
тестовый образ и запускает контейнер. Работающие сервисы не пересоздаются.
При следующих запусках без изменения тестов:

```bash
bash scripts/test.sh --no-build
```

Для выбора одного сценария:

```bash
bash scripts/test.sh --no-build --grep 'TinyMCE'
```

Нужны действующие пароли студента и администратора коллектора в `.env`.
При недоступности npm можно собрать образ из локальных архивов зависимостей:

```bash
bash scripts/test.sh --offline
```

Этот режим требует уже скачанного базового образа Playwright и архивов пакетов
из текущего lockfile в `e2e/npm-cache/`. Архивы предоставляются отдельно;
эта папка исключена из Git. Установка выполняется через `npm ci --offline`,
а сетевой доступ команд сборки отключён. Основной Dockerfile остаётся для
обычной сборки из чистого клона. После успешной сборки используйте `--no-build`.

Тесты используют существующий аккаунт `student` и демокурс `COLLECTOR-DEMO`.
Они обновляют ответ на демозадание и создают попытки демотеста и события.
Пользовательские базы не очищаются; применяйте модуль на демонстрационном стенде.
Внутренние прокси поддерживают стандартные локальные HTTP-адреса стенда.

## Что проверяется

1. Вход в Moodle с переходом обратно на запрошенный учебный материал.
2. Подключение плагина, настоящие действия мыши, copy/paste, scroll и pagehide.
3. Доставка новых событий через frontend и backend, включая пользователя и курс.
4. Настоящая вставка в iframe TinyMCE и сохранение ответа на задание.
5. Запуск и завершение теста `2 + 2`, проверка правильности ответа `4`.
6. Вход в интерфейс статистики, запрос данных и отображение новых событий в таблице.

Проверки сгруппированы в пять сценариев в `tests/smoke.spec.mjs`.
Каждая проверяемая страница получает случайный параметр `e2e_run`;
старые записи не могут подтвердить доставку новых событий.
Для проверки доставки используется GET API, а не прямое чтение MongoDB.
События, ответы API и страницы Moodle в этих сценариях не подменяются.
Не проверяются сетевые обрывы, все виды событий и все темы/версии Moodle.

## Результат и диагностика

Код завершения `0` означает успех всех выбранных тестов; ненулевой — сбой.
Результаты доступны в `reports/e2e/`:

- `html/index.html` — отчёт;
- `junit.xml` — машинный результат;
- `test-results/` — screenshot, video и trace упавших сценариев;
- `demo.json` — ссылки, использованные в текущем прогоне.

Чтобы открыть интерактивный отчёт, его можно раздать локально:

```bash
python3 -m http.server 18083 --bind 127.0.0.1 --directory reports/e2e/html
```

Откройте `http://localhost:18083`. Отчёты исключены из Git.
Контейнер запускается с UID/GID пользователя, чтобы результаты оставались
доступны для редактирования без `sudo`.

GitHub workflow `Browser smoke tests` запускается вручную и прикладывает отчёт.

## Сопровождение модуля

`local-proxy.mjs` сохраняет настроенные Moodle origins внутри тестового контейнера,
направляя запросы к Docker-сервисам. Он не требует изменения `MOODLE_URL`, CORS,
портов или данных рабочего стенда. Тестовый контейнер не публикует порты на хосте.

Для проверки HTTP-прокси без браузера после `npm ci` в этой папке:

```bash
npm run check
```

При обновлении Playwright измените версию в `package.json` и Dockerfile вместе,
пересоздайте `package-lock.json` и пересоберите тестовый образ.
