# Ручная установка плагина в отдельный чистый Moodle

Используются локальные образы проекта Moodle 5.0.2 и MariaDB 10.11: скачивания,
сборки образов и npm нет. Нужны Python 3.10+ и исходники плагина в репозитории.

## 1. Запустите коллектор

Если backend, frontend и MongoDB уже работают, пропустите этот шаг.

```bash
docker compose up -d --no-build --pull never --wait --wait-timeout 900 backend frontend
```

Установка коллектора и `.env` должны быть подготовлены по основному README.

## 2. Создайте временный Moodle

```bash
python3 scripts/manual-moodle.py start
```

Скрипт выбирает свободный порт, создаёт отдельную сеть и два контейнера,
устанавливает пустой Moodle без нашего плагина и демокурса. Адрес, пароль admin,
ZIP и путь для Windows выводятся после установки. Браузер открывайте на том же
компьютере, где работает Docker/WSL.

Оставьте этот терминал открытым: Enter или Ctrl+C завершает опыт и удаляет стенд.
Для фиксированного порта: `python3 scripts/manual-moodle.py start --port 18084`.

На время опыта новый origin добавляется в CORS работающего коллектора;
backend кратко пересоздаётся, затем nginx перечитывает его адрес. Используется
тот же образ backend и его действующие ключи, настройки БД и ограничения ресурсов.
Основной `.env`, основной Moodle и его MariaDB не изменяются.

Временные MariaDB и Moodledata находятся в tmpfs, по 512 MiB каждый. Остановка
соответствующего контейнера теряет эти данные. Пределы памяти контейнеров:
MariaDB — 1 GiB, Moodle — 1.5 GiB; tmpfs входит в эти пределы. Это стенд для
небольшого ручного опыта, не для импорта большого курса или дампа прода.

Если образ автоматически не найден, укажите уже имеющиеся имена:

```bash
python3 scripts/manual-moodle.py start \
  --moodle-image moodle_js_actions_collector-moodle:latest \
  --mariadb-image mariadb:10.11.11
```

Имя первого образа зависит от имени вашего Compose-проекта; посмотрите `docker image ls`.
Если основной коллектор запускается через другой Compose-файл:

```bash
python3 scripts/manual-moodle.py start --compose-file docker-compose.prod.yaml
```

## 3. Установите плагин руками

1. Откройте выведенный адрес временного Moodle. Войдите как `admin` с выведенным паролем.
2. Откройте `/admin/tool/installaddon/index.php`: **Site administration → Plugins → Install plugins**.
3. Выберите выведенный `local_actioncollector.zip`. В Windows используйте выведенный WSL-путь.
4. Подтвердите проверку ZIP и завершите установку/обновление БД через UI.
   Здесь обновляется только отдельная временная БД Moodle.
5. Откройте `/admin/settings.php?section=local_actioncollector`.
6. Включите **Enable collection**.
7. Во втором терминале выполните:

   ```bash
   python3 scripts/manual-moodle.py settings
   ```

8. В **Collector API URL** и **Collection key (write only)** перенесите значения
   этой команды. Ключ — только текст после `Collection key:`, без подписи.
9. Сохраните и перезагрузите страницу Moodle.

Архив собирается из текущих исходников через `scripts/build-moodle-plugin.py`.
Адреса и ключи в ZIP не вшиваются. Тестовая `playground.php` в него не включается.

## 4. Создайте данные через UI

1. Создайте курс, например `Manual check`, и добавьте в него **Page**, **Assignment**
   с онлайн-текстом и **Quiz** с одним простым вопросом.
2. Создайте пользователя `manual.student`, почта `manual.student@example.com`,
   пароль задайте сами; снимите обязательную смену пароля при первом входе.
3. Зачислите его в курс с ролью Student.
4. В отдельном приватном окне войдите этим студентом.

Cron запускается автоматически раз в минуту. Если Moodle сообщает про незавершённый
перенос вопросов в question bank, подождите минуту или выполните:

```bash
python3 scripts/manual-moodle.py cron
```

## 5. Короткий чеклист

- Откройте Page, покликайте, прокрутите, скопируйте текст, переключите вкладку.
- В Assignment напечатайте, удалите и вставьте текст. Сохраните ответ, откройте его снова.
- Пройдите Quiz и завершите попытку. Проверьте, что ответ сохранился в Moodle.
- Измените обычный HTML-чекбокс и выпадающий список в формах Moodle.
  Нестандартные виджеты без `input[type=checkbox]`/`select` могут не давать такие события.
- Войдите в коллектор его существующей учётной записью из `.env`.
  Это отдельная учётная запись от admin временного Moodle.
- Нажмите **Обновить**. Найдите свой курс/почту, проверьте URL со случайным портом,
  пользователя, время и события. Администратор Moodle тоже собирается — не спутайте его со студентом.
- Для чекбокса ожидается `checked`, для select — индексы выбранных пунктов;
  содержимого ответов, клавиш и clipboard в событиях быть не должно.
- Выгрузите **Метаданные страниц**: проверьте `browser` (User-Agent), `title`,
  `page`, `window` и отсутствие `page_html`. Браузер доступен именно в этой выгрузке.

Для проверки отказа API сначала откройте страницу со студентом и дождитесь запуска
трекера. Затем через DevTools заблокируйте запросы к адресу API коллектора.
Покликайте и сохраните ответ на Assignment: ответ должен сохраниться в Moodle.
После снятия блокировки подождите около минуты для повторной отправки очереди.

На странице Moodle в Console можно посмотреть состояние без вывода ключа:

```javascript
(() => {
  const c = window.actionCollector;
  return c ? {ready: c.ready, queued: c.queued, sent: c.sent, dropped: c.dropped, error: c.error} : null;
})()
```

`ready: true` подтверждает запуск. При штатной связи очередь должна уменьшаться,
`sent` — расти. При переполнении ограниченной очереди `dropped` может увеличиваться.

## 6. Диагностика и завершение

```bash
python3 scripts/manual-moodle.py status
python3 scripts/manual-moodle.py logs
```

Если терминал запуска закрыт, завершить из другого терминала:

```bash
python3 scripts/manual-moodle.py stop
```

Штатное завершение восстанавливает CORS и удаляет только временные контейнеры,
сеть и каталог `/tmp/moodle-rehearsal-*`. События в коллекторе сохраняются.
Если очистка не удалась, скрипт оставляет приватные файлы восстановления и просит
повторить `stop`. Не удаляйте их раньше восстановления.

После аварийного выключения, если файлы `/tmp` уже потеряны, обычную конфигурацию
backend можно восстановить из репозитория:

```bash
docker compose up -d --no-deps --no-build --pull never --wait backend &&
docker compose exec -T frontend nginx -s reload
```

Для основного режима с `docker-compose.prod.yaml` добавьте `-f docker-compose.prod.yaml`
к обеим командам. Не выполняйте `docker compose down -v` для основного проекта.

Пароль временного admin и ключ из `settings` не публикуйте вместе с логами.
